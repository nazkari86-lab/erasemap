# Erasure Tomography Redis v1 preregistration

This opt-in transfer tests the frozen ET decoder against a real digest-pinned Redis process rather
than the local filesystem/SQLite carrier laboratory. Four project-authored Redis recovery
workflows represent backup restore, checkpoint redeployment, legacy export import, and delayed
queue replay. The same three-row `k=1`, `e=0` matrix is used.

Five cases are frozen: one per single active mechanism and one no-recurrence control. Each case also
stores an unrelated retained synthetic subject. After localization, the carrier key for the
localized mechanism is removed, recovery is replayed, and both target recurrence and retained loss
are observed.

The primary gates require 4/4 exact localization, the safe decision, zero false localization,
production/oracle equality, zero post-control recurrence, zero retained loss, and three tomography
rounds versus four individual mechanism checks.

This experiment is project-authored live stock-service transfer. It is not an independently
designed challenge, not a real organization, and not evidence that Redis keys reproduce the full
semantics of eGov, FaceID, banking, or biometric model infrastructure.
