# EraSeMap: простой сценарий защиты

## Главное предложение

**EraSeMap — один алгоритм, который находит зарегистрированные следы данных человека, удаляет их
вместе с влиянием на модель и проверяет, что они не вернутся позже.**

## Три шага

1. **FIND — найти.** Где остались исходные записи, копии, биометрические шаблоны, векторы, резервные
   копии и влияние в обученной модели? Может ли скрытый путь восстановления вернуть их?
2. **ERASE — стереть.** Какой минимальный набор физических действий и удаления влияния из модели
   (machine unlearning) закрывает
   все найденные пути? Если быстрый unlearning не проходит проверки, используется точное
   переобучение без удаляемых данных или выдаётся `INCOMPLETE`.
3. **PROVE — проверить.** Не вернутся ли данные после restore, sync, cache warm-up, index rebuild или
   повторного развёртывания модели? Сертификат выдаётся только после успешного replay.

## Версия на 30 секунд

После локального удаления данные человека могут остаться в шаблоне лица, векторном индексе, кэше,
резервной копии или модели, а позже восстановиться. EraSeMap одним алгоритмом делает три вещи:
находит все зарегистрированные пути, удаляет их вместе с влиянием на модель и проверяет во времени.
Результат — либо `COMPLETE_WITHIN_ENVELOPE`, если проверка пройдена, либо конкретный оставшийся путь
`INCOMPLETE`, либо `UNVERIFIED`, когда данных для вывода недостаточно.

## Версия на 3 минуты

### 0:00–0:40 — проблема

Обычная система часто считает удаление завершённым после удаления основной строки. Но распознавание
может продолжаться по активному шаблону, поисковому вектору, кэшу, backup или обученной модели.
Поэтому мой вопрос был не «появился ли статус “удалено”?», а «остался ли хоть один пригодный путь к данным?»

### 0:40–1:25 — алгоритм

Сначала FIND строит граф: узлы — места хранения и производные, рёбра — копирование, обучение,
синхронизация и восстановление. Безопасные тестовые операции помогают различить ограниченный набор
скрытых recovery-путей. Затем ERASE выбирает минимальный достаточный план. Machine unlearning здесь
не отдельный проект, а обязательное действие для модельной ветки; оно сравнивается с точным
переобучением. Наконец PROVE повторяет будущие операции и разрешает сертификат только когда данные
не возвращаются. Неизвестное никогда не считается успехом.

### 1:25–2:35 — результаты

- На 60 frozen случаях со stock Keycloak, MLflow и Qdrant EraSeMap дал `0/60` ложных `COMPLETE`;
  native status ошибся `45/60`, полный typed audit — `5/60`.
- В bounded hidden-graph эксперименте активный FIND потребовал 7 проб против 13 у frozen random и
  49 у exhaustive, без false-confident решений.
- В 20 парных real-process опытах targeted ERASE был в среднем геометрически в 17.64 раза быстрее
  rebuild-all и записал на 94.62% меньше байтов при нулевой потере retained-данных.
- Temporal PROVE обнаружил 30 из 30 латентных рисков; после выбранных controls было 0 из 30
  физических возвратов. Snapshot audit эти будущие риски не обнаруживал.
- Exact action solver совпал с exhaustive oracle во всех 3,072 проверках; temporal solver — во всех
  16,384.
- На реальной открытой модели Qwen2.5-1.5B быстрый unlearning не прошёл все frozen gates. Это
  отрицательный, но важный результат: EraSeMap не назвал модель очищенной и сохранил exact retraining
  как безопасный вариант.

### 2:35–3:00 — вклад и граница

Lineage, deletion testing и machine unlearning существовали отдельно. Мой вклад — единое
fail-closed решение, которое связывает физические остатки, влияние в модели, минимальный план,
проверку будущего восстановления и сертификат. Я не утверждаю production-внедрение в FaceID или
eGov. Внешний независимо написанный hidden challenge подготовлен, но его результат пока
`NOT_COLLECTED`.

## Демонстрация за 60 секунд

```bash
erasemap showcase --repo-root . --output outputs/jury-showcase-v1
open outputs/jury-showcase-v1/index.html
```

1. Показать исходный `INCOMPLETE`: основная строка удалена, активный шаблон остался.
2. Провести пальцем по трём блокам: FIND → ERASE → PROVE.
3. Показать один выигрыш по качеству, один по стоимости и один отрицательный ML-результат.
4. Самому назвать границу: сертификат действует только внутри зарегистрированной карты и времени.

## Короткие ответы

**Почему это один алгоритм?** Все внутренние вычисления приводят к одному решению и не имеют
самостоятельного пользовательского результата.

**Machine unlearning убрали?** Нет. Он обязателен внутри ERASE, когда данные повлияли на модель.

**Как алгоритм узнаёт о другой системе?** Доверенный adapter регистрирует хранилища и наблюдает
безопасные тестовые операции. Если coverage неизвестен, ответ только `UNVERIFIED`.

**Почему не просто удалить всё?** Blanket deletion может быть безопасным, но дорогим и повреждать
данные других людей. EraSeMap ищет минимальный достаточный зарегистрированный план.

**Что означает COMPLETE_WITHIN_ENVELOPE?** Удаление доказано для указанной карты, verifiers,
модели, transition set и временного окна — не для неизвестной инфраструктуры вообще.

## Последняя фраза

EraSeMap не обещает увидеть сервер, который никто не зарегистрировал. Его правило простое:
пока в зарегистрированной системе остаётся пригодный путь, модельное влияние или непроверенный
канал, удаление не будет названо завершённым.
